## 必修 1：统一权限门禁与业务功能场景冲突（高优先级，建议先于 P1 修）

位置：`qiaomi/companion_policy.py:49-52`。

当前 `allowed(feature)` 对所有 F01–F10 一刀切要求：非 `sulking` 且 `phase == 'idle'`。这样会导致：

- **F03 做梦**需要 `phase == 'sleeping'`，但 `allowed('F03')` 在睡眠时返回 `False`。`qiaomi/personality.py:384-388` 也明确将猫咪进入 `sleeping` 阶段。
- **F09 妈妈回来**按 v0.6 规格应在闹脾气时可以温柔提示“妈妈回来啦……哼！”而**不自动和好**，当前门禁全部屏蔽 `sulking`。
- **F10 回忆事件**应该能从摸头、洗澡完成、四次安抚成功等真实事件记录，事件发生时可能处于 `care`、`touch` 或 `soothing`，不能只允许 `idle`；它不该占用动画独占权。
- **F05 情绪微动作**按规格是现有主动作的可选子层，不应与所有主动作使用相同的 `idle` 条件。

建议将政策分为：①绝对禁止场景（游戏模式/系统睡眠/退出）；②短动画类视觉事件（按每个功能的允许阶段/闷气状态限定）；③被动事件记录（不抢占动作、仅本地写入、受隐私设置控制）；④临时鼠标观察（可与普通可见动画并存但绝不影响触摸）。不要通过把全局条件简单放宽为 `True` 解决。

**新增测试：** 睡眠中允许一条 F03 梦泡且不重叠旧梦话；F09 闷气提示后闷气与四次摸摸计数保持不变；F10 在洗澡完成/首次互动/成功和好时写入一次、游戏模式不写；F05 不干扰主动作。

## 必修 2：新事件取消的信号先后顺序（高优先级，P1 接入前解决）

位置：`qiaomi/app.py:299-303`，以及 `qiaomi/personality.py` 的 `pet.interaction.connect(self.interact)` 和拖拽连接。

`Controller` 在现有 `PersonalityEngine` 和 `CareEngine` 已连接猫咪交互信号后，才把 `companion_policy.cancel()` 连到 `pet.interaction` / `pet.drag_started`。目前 P0 没有实际新增效果，因此还未出现可观察的覆盖问题；但未来新增效果取消回调**可能晚于**已有摸头、拖拽反馈执行，继而把刚播放的新动画/气泡重置。

建议统一一个“先撤销被动效果→再处理原有触摸/拖拽”的前置入口，或明确规定 cancel 回调只能清理自己拥有的局部覆盖物，不能更改猫咪已更新的主姿态。**不能用断开旧交互信号来实现**。增加测试：F01/F03/F07 正播放时摸头、揉爪、拖拽，旧热区反馈完整执行；一次长按不抵四次独立摸摸；不残留气泡或计时器。

## 必修 3：事件归属权需要区分“长期观察”和“短时特效”（中高优先级）

位置：`qiaomi/companion_policy.py:53-65`。

`self.active` 当前只允许一个全局拥有者。如果未来 F01 鼠标观察持续 claim 而不 release，会阻塞做梦、趣味事件、收藏提示等。建议：仅短时、独占的视觉主效果申请 `claim()`；F01 坐标采样与 F10 数据记录不长期占用该 token；在 finish/cancel/异常/隐藏/游戏模式路径统一释放，使用 generation/token 避免旧定时回调误结束新动画。新增交替运行和抢占测试。

## 必修 4：P0 升级备份版本号与命名不一致（中优先级）

位置：`qiaomi/app.py:137-140`、`qiaomi/upgrade.py:8-36`。

新增 P0 marker 是 `.upgrade-v0.6.0-p0.json`，但 `ensure_upgrade_backup()` 内写出的 `record['version']` 仍为 `0.5.0`，目录为 `pre-v0.5.0-...`，备份描述同样使用 0.5.0。**这是实际存在的标签不一致，不代表已有数据被删除。**

建议安全地为 `ensure_upgrade_backup` 添加目标版本参数或明确独立的 P0 快照逻辑，并兼容已经生成的 marker；验证备份目录、SQLite WAL 快照与恢复说明，不要重复备份导致空间浪费，更不要修改/覆盖已有备份、删除旧版本用户数据。
