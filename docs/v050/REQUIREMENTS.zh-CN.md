## 1. 产品目标与不可妥协的原则

**目标**：把敲咪从“会回应触摸的桌宠”升级为“会自己吃饭、洗澡、休息、玩耍的橘金色小猫咪”。用户想互动时可以亲自照顾；忙碌时可以一键完成；完全不管时，敲咪也会自己照顾自己。

- **纯娱乐，零养成负担**：敲咪永远不会饿死、死亡、生病、受伤或因用户不登录而遭到惩罚。没有医疗系统、氪金、体力门槛或资源付费。
- **用户不必持续照顾**：自动进食、自动清洁、自动休息、自己娱乐，所有状态可恢复。
- **互动优先于自发行为**：用户点击、抚摸、拖拽、喂食或洗澡，敲咪应有即时、正确的反馈；自主动画可以被温和中断。
- **尊重现有角色与资产**：敲咪仍是橘猫×金渐层、淡虎斑、圆脸大眼、微胖蓬松、奶白色嘴边/胸腹/四只白手套、粉鼻与粉肉垫、两颗小虎牙的猫咪。继续使用现有粉色向尾喵睡衣及既有图标/画风；不要擅自换成人形或其他物种。

## 2. 必须保留的 v0.4.1 基线

下列是**不允许回退的既有体验**；Codex 需要先在仓库中逐一核对实现，再做兼容性测试：

1. 桌宠窗口透明、可拖动，可贴屏幕上/下/左/右边缘；不出现多余矩形背景、穿帮描边、异常裁剪或重复尾巴。
2. 身体分区互动：耳朵、头、下巴、肚子、前爪、后爪、尾巴；原有触摸反馈不能被新增菜单或玩具抢占。
3. 长时间未摸敲咪的既有冷落/生闷气机制（先前设定为约 10/20/30 分钟阶段），包括主动来到屏幕中央和**需要四次相互独立的摸摸才能哄好**；不能靠悬停或一次长按作弊。
4. 原有自主行为：看书、游戏机、吃东西、打瞌睡、趴睡、玩毛线球、洗脸、伸懒腰等；v0.5.0 是扩展而不是替换。
5. **游戏模式**：由用户主动开启；隐藏桌宠，停止动画、生活调度、语音监听/识别/播放（如当前设计要求）及不必要的后台计算；**不自动退出**；只允许从系统托盘手动恢复。恢复时保留既有“妈妈！你怎么才回来！”重逢反馈。
6. 托盘图标和菜单、单实例运行、原有无控制台黑窗的启动体验，以及开机自启设置（若已有）不受影响；避免启动旧版本的残留入口。
7. 管家界面奶白浅色/深蓝深色主题及选择记忆；原有 100% / 110% / 125% / 150% 字体或界面缩放设置保持有效。
8. 已有长期记忆、聊天、本地模型、语音相关配置与声音设置继续有效；**语音唤醒/持续监听默认关闭**，除非用户明确开启。

> 若部分功能在实际 v0.4.1 中尚未完成：不要伪称已存在；在最终报告中注明“已存在 / 本次补齐 / 尚待完成”。本次以新增生活系统及不回归为主。

## 3. 四大生活数值：状态定义与规则

| 名称 | 范围 | 主要变化 | 低值后的动作 |
|---|---:|---|---|
| 饱腹度 `hunger_satiety` | 0–100 | 活动时缓慢下降；进食上升 | ≤30：自主取食或吃饭 |
| 清洁度 `cleanliness` | 0–100 | 正常活动时缓慢下降；清洗上升 | ≤30：自主清洁/洗澡 |
| 精力值 `energy` | 0–100 | 玩耍消耗；休息和睡觉恢复 | ≤25：打瞌睡或回窝睡觉 |
| 心情值 `mood` | 0–100 | 逗猫、抚摸可上升；无聊时缓慢波动 | ≤30：主动找玩具、看书等娱乐 |

**具体约束：**

- 默认使用平稳、中性的初始值（例如饱腹 80、清洁 90、精力 80、心情 80）；只在新用户无存档时初始化，已有状态不得重置。
- 仅在**正常运行且桌宠活动可调度**时按有效运行时间缓慢变化；电脑关机、程序退出、系统休眠和游戏模式期间**一律不追扣、不离线衰减**。
- 启动/恢复后读取上次保存值；如值低则安排正常的自主照顾，但**不能一次性连续触发大量积压事件**。
- 所有值限定在 `[0, 100]`；无论降到多少，均无死亡、生病、伤害或不可逆惩罚。可通过自动行为无成本恢复。
- 变化速率、阈值、动画时长设为易于调试的常量/配置项，避免散布在 UI 代码中；默认节奏宜慢，用户不会每几分钟被迫照顾。
- **心情与“生闷气待哄”分离**：原先必须四次独立抚摸的生闷气逻辑应保留单独标记/计数；敲咪自主玩耍恢复心情值，不可自动清除生闷气状态或绕过四次触摸。
- 仅必要时持久化（事件完成、定期节流、退出时），不要每帧写数据库。

## 4. 喂食系统（手动 + 一键 + 自动）

### 4.1 手动喂食

- 在敲咪的现有右键菜单/管家界面中增加“喂食”入口，不覆盖原来点击/拖拽逻辑。
- 可选择**小鱼干**、**猫饭**；喝水动作可作为附加轻量互动，不要求单独数值。
- 小鱼干：双爪捧着吃、舔嘴巴；猫饭：跑向小碗/坐好、低头吧唧吃；动画可按现有资产简化。
- 完成后提升饱腹度，播放对应的可爱回应；允许用户中断，不能卡死在吃饭状态。

### 4.2 一键喂食【必须完成】

- 入口：右键菜单或状态面板中的 **“一键喂食”**，单击一次即可使用。
- 行为：播放**短版**进食动画/反馈，**饱腹度直接恢复 100**；无需打开复杂菜单、选择食物或等完整长动画。
- 动画可跳过；重复快速点击不应出现叠加动画、负数、错乱、重复写库或卡死。以“本次喂食仅生效一次”的幂等逻辑处理。

### 4.3 自主喂食【必须完成】

- 饱腹度低或长时间无人理会时，敲咪可以主动去饭碗、拿出小鱼干，自主进食并恢复数值。
- **不消耗金币、背包物品或任何用户资源**，不需要用户点确认。
- 可能触发“偷吃小鱼干被妈妈抓包”的趣味回应；被点击后先处理当前进食状态，再响应用户，不丢失操作。

## 5. 洗澡与清洁度系统（手动 + 一键 + 自动）

### 5.1 手动洗澡

入口：“洗澡澡”。用户用鼠标参与流程，阶段如下：

1. **进浴缸**：桌宠切换到浴室/盆的轻量化视觉场景，呈现温暖、卡通化效果。
2. **搓泡泡**：鼠标轻揉头、背、肚子、前后爪等区域，触发对应可爱表情和泡泡效果；不能破坏既有身体热区。
3. **冲洗**：泡泡消退；有轻量化水花/甩毛反馈。
4. **吹干/烘干**：使用现有“专属猫咪烘干机”世界观的安全卡通动画；无真实高温、危险设备操作指导。
5. **完成**：清洁度到 100；毛发恢复蓬松，出现短暂香香/闪亮效果与台词。

手动流程应有明确完成/取消/跳过方式。每个阶段都不能锁死鼠标或遮挡整个桌面。

### 5.2 一键清洗【必须完成】

- 入口：右键菜单或状态面板中的 **“一键清洗”**。
- 单击后直接播放**简短洗澡 + 吹干**动画，**清洁度恢复 100**；不进入逐区域交互。
- 允许跳过短动画；确保按钮不会反复叠加流程或把桌宠困在浴缸中。

### 5.3 自主洗澡【必须完成】

- 清洁度 ≤30 或长时间无人照顾时，敲咪自行执行短版清洁/洗澡流程，恢复到舒适范围或 100。
- “自己洗”与“妈妈帮洗”两种体验并存；自动自理不请求用户、无资源消耗。
- 洗澡只改变娱乐向数值、画面和话语；**不会出现生病、健康值或卫生惩罚**。

## 6. 逗猫与玩具互动

**至少完成三种入口可用、反馈不同的玩具：**

| 互动 | 敲咪反应 | 结束条件 |
|---|---|---|
| 逗猫棒 | 视线/脑袋追随、伸爪扑击；可随机扑空 | 用户停止或切换操作 |
| 毛线球 | 拨球、追球、抱球打滚 | 短动画完成或被中断 |
| 玩具老鼠 | 压低身体、翘屁股、扑向目标 | 短动画完成或被中断 |

- 鼠标移动是玩具输入，不应让透明窗口吞掉其他应用的鼠标操作；尽量使用宠物局部交互区域。
- 适量随机成功/失败及“被抓包”反应，避免机械重复；但同一时间仅运行**一个主要活动**。
- 玩耍可提高心情、消耗少量精力；精力低时可改为低强度逗猫，不设置“不能玩”的强制限制。
- 敲咪被拖拽、摸头、切换游戏模式或触发其他高优先级动作时，玩具交互应安全退出。

## 7. 自主“摸鱼”与生活调度

### 7.1 触发条件

- 以**用户多久没有直接互动敲咪**为依据；不等于 Windows 全局没有鼠标/键盘输入。
- 约 **3–5 分钟**没有抚摸/拖拽/菜单操作后，进入可随机执行的自主活动状态；遵守原有 10/20/30 分钟冷落与生闷气判定。
- 可选活动：**玩粉色游戏机、偷吃小鱼干、打瞌睡**；并与旧有看书、趴睡、玩毛线球、舔毛洗脸、伸懒腰等动作共存。
- 选择需考虑四项数值、随机权重和最小冷却时间；避免连续重复同一种动作，避免“吃饭→洗澡→吃饭”死循环。

### 7.2 行为示例

- 精力高：坐着玩游戏机，偶尔“赢啦”“怎么输了”；用户摸到时藏游戏机。
- 饱腹低：主动吃猫饭或小鱼干；用户摸到时表现“被抓包”。
- 清洁度低：主动洗澡、吹干、恢复蓬松。
- 精力低：打哈欠、脑袋点点、趴睡/回窝；恢复精力后醒来伸懒腰。
- 心情低：自己娱乐/找玩具；但不能自动解除原有“需要四次抚摸”的生闷气规则。

### 7.3 行为优先级与互斥

按以下顺序执行：

1. **游戏模式（绝对最高；深度静默）**
2. 用户直接操作（拖拽、摸摸、点击、退出/托盘命令）
3. 用户发起的手动喂食、洗澡、逗猫/一键操作
4. 原有生闷气/和好等关键事件（不能被自主生活吞掉）
5. 自主照顾（饱腹、清洁、精力优先）
6. 自主摸鱼及普通待机

实现可中断的轻量状态机（例如 `IDLE / AUTONOMOUS / FEEDING / BATHING / PLAYING / RESTING / SULKING / GAME_SLEEP`，具体命名以仓库风格为准），并提供统一的取消/切换出口。**绝不能同时播放洗澡、喂食、逗猫和打瞌睡。**

## 8. 操作界面与用户体验

### 8.1 右键菜单建议

```text
敲咪 🐈
├─ 喂食（手动选择）
├─ 一键喂食
├─ 洗澡澡（妈妈帮洗）
├─ 一键清洗
├─ 逗猫（逗猫棒 / 毛线球 / 玩具老鼠）
├─ 查看生活状态
├─ 游戏模式（沿用原逻辑）
└─ 现有其他菜单项（原样保留）
```

### 8.2 状态面板

- 显示四项数值、简洁进度条和当前行为，例如“偷偷玩游戏机中”“吃饱打瞌睡”。
- 保持浅色/深色主题及 100/110/125/150% 缩放的兼容性。
- 不要频繁弹窗催促喂食或洗澡；状态提示为轻量气泡或面板信息即可。
- “自动照顾自己”默认开启；如现有设置页易于扩展，可提供开关并持久化，关闭后也**不产生死亡/生病等负担**。

### 8.3 演出与文案语气

猫系、活泼、黏人、轻微傲娇；可出现“妈妈！敲咪没有偷吃！”“刚洗完香香啦！”“这把敲咪要赢！”等短句。保留既有气泡/语音规则；**生活系统不可默认开启麦克风、自动触发重型本地模型推理或干扰用户电脑声音**。

## 9. 数据、性能与兼容性要求

### 9.1 数据存储

- 优先复用当前配置文件/SQLite/数据访问封装，选择与现有工程一致的做法；必要时新增独立生活状态表或配置键，提供**可回滚、兼容旧数据**的迁移。
- 至少保存：四项数值、上次持久化时间、必要的生活设置；原有记忆、语音配置、主题与角色信息绝不能被迁移覆盖。
- 数据安全：值范围校验、缺失字段默认值、损坏记录可恢复；避免频繁写盘；禁止从删除过的 0.4 之前版本读取假定存在的文件。

### 9.2 性能

- 正常桌面待机时使用低频调度（建议秒级而非逐帧扫描），只在动画播放时刷新需要变化的画面；严禁忙等待循环。
- 空闲/游戏模式不得运行不必要的模型推理、语音识别、动画计时器、媒体解码或全屏透明捕获窗口。
- **游戏模式**应隐藏或静止桌宠、暂停数值衰减与自主生活逻辑，并只保留必要的托盘手动恢复能力。退出游戏模式不补算时间，也不立刻爆发排队动画。
- 资源应可释放；切换游戏模式、退出或异常中断后不遗留进程、线程、窗口或声音。

### 9.3 视觉与运行

- 保持原透明窗口、拖动和贴边；新浴缸、饭碗、泡泡、玩具等优先以局部透明叠加/可复用帧呈现，不能引入黑底、白底和明显矩形边框。
- 贴边状态注意裁剪/遮挡：不要出现两条尾巴（真正的橘尾与睡衣装饰尾需区分），也不要出现重复轮廓。
- 兼容现有 Windows 运行/打包流程；保留系统托盘、开机启动目标版本、单实例和“无黑色命令窗口”体验。不要无要求地提升系统权限。

### 推荐实施顺序

1. **清点 v0.4.1**：确认模块与数据路径、旧功能基线；先备份重要数据。
2. **实现生活状态层**：四大数值、持久化、时间暂停规则、迁移和单元测试。

4. **接入操作 UI**：手动喂食/洗澡/逗猫、一键喂食、一键清洗、状态面板。
5. **接入动画/音效**：优先复用原素材；资源缺口清楚标注，不牺牲逻辑可用性。
6. **回归、打包与报告**：重点测游戏模式、4 次安抚、托盘无黑窗、存储迁移。
