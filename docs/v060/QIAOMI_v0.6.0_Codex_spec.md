# QIAOMI AI v0.6.0｜UI 与陪伴玩法扩展开发规格

> **文件性质**：可直接交给 Codex 的功能、视觉、交互、架构、验收一体化规格  
> **版本关系**：在现有 v0.4.1 → v0.5.0《敲咪的日常生活（零负担陪伴版）》的基础上继续增量开发，新增部分建议定名 **v0.6.0「敲咪的小小世界」**。版本号仅为建议，实际由当前仓库状态决定。  
> **平台**：Windows 11 桌面应用，沿用现有项目技术栈；曾用 Python 3.12 / PySide6 / SQLite / 本地 Ollama，必须以仓库实情为准。  
> **设计目标**：新增 10 种有趣且低打扰的陪伴行为，让敲咪「自己会生活、会偷偷搞事情、也会记得和妈妈的相处」，而不是变成有负担的养成游戏。

## 0. Codex 必须先执行的项目审查

1. 查看当前实际版本、入口、项目结构、素材格式、角色动画驱动、身体区域热区、透明窗口鼠标穿透、托盘、设置/主题、生活数值、SQLite/记忆、游戏模式、打包逻辑；**先确认 v0.5.0 是否已经完成**。未完成部分先按旧规格补齐或给出先后实施计划，**绝不能把未完成的功能当成已完成**。
2. **只做增量修改**：不重写桌宠、不删除旧素材、不覆盖个人记忆/聊天记录/设置、不修改已定义的形象。任何 Schema 修改先备份并可向后兼容；保留无黑窗、单实例、开机自启、托盘退出、旧版本入口清理。
3. 先跑旧测试，按模块实现、跑回归、再制作集成包；每阶段提供真实修改文件、运行测试、留存问题。UI 与游戏模式并行开发时，**游戏模式深度静默优先于任何新功能**。
4. 附件的 HTML 是 **视觉与交互参考样机，不是要求引入浏览器内核、Electron 或重写技术栈**。原生 PySide6 界面优先；若现有代码不使用 PySide6，保持当前方案。

## 1. 不可变的产品设定

- **敲咪形象**：橘金色、浅虎斑、小圆脸、大眼睛、奶白胸腹及四只白手套、粉鼻与粉色肉垫、两颗小虎牙，**短毛、略圆润的小胖咪，不得画成长毛或蓬松披毛**；保留现有粉色向尾喵睡衣、统一图标与现有素材，不要换人形、强行加头发或重新设计猫。
- **保留旧功能**：透明可拖拽桌宠、屏幕四边贴边、多屏/高 DPI、耳头下巴肚皮前后爪尾巴分区、现有自主看书/游戏机/吃饭/摸鱼动作、约 10/20/30 分钟冷落与来到中央生气、**四次独立摸摸和好**、记忆、聊天、本地模型、语音、托盘、奶白浅色/深蓝深色主题、100/110/125/150% 缩放。
- **保留 v0.5.0 生活系统**：饱腹、清洁、精力、心情四项 0–100 数值；手动/一键/自动喂食与洗澡、三类玩具、自动照顾、不离线追扣、无生病/死亡/惩罚。所有新玩法不能引入金币、养成压力、付费道具、必须签到或资源耗尽机制。
- **游戏模式硬约束**：只能手动进入、**只能从托盘手动退出**。进入时隐藏桌宠/界面，停止动画、事件、回忆采样、生活衰减、鼠标观察、系统闲置检测、计时器、语音与不必要线程，不自动退出、不补跑积压事件；恢复仅保留原有“妈妈！你怎么才回来！”特定反馈。新玩法不能绕过这一条。
- **数据安全与隐私**：本地优先，不默认开麦克风、不读取键盘内容、不记录应用名称/屏幕图像/窗口文字、不上传数据、不自动调用 Ollama 生成大量文案；新玩法以本地事件和预设短句驱动。

## 2. 完整视觉方案（桌宠本体 + 管家界面）

### 2.1 美术方向：奶油猫窝 / 深夜蓝猫窝

**浅色主题**：背景 `#FFF9F2`、卡片 `#FFFFFF`、边线 `#EFE4DB`、主文字 `#4B3E38`、次文字 `#8E8079`、橘色主色 `#F3A765`、粉色强调 `#F7B8C8`、薄荷绿 `#A5D7C5`。  
**深色主题**：背景 `#15263C`、卡片 `#1D314B`、边线 `#35506A`、主文字 `#F8F3ED`、次文字 `#B9C6D4`、橘色主色 `#FFBA78`、粉色强调 `#ED9DBA`。  
卡片圆角 14–18 px，按钮圆角 10–12 px；原生字体优先“Microsoft YaHei UI / 微软雅黑 / 系统 sans-serif”；留白、轻阴影、橘色主按钮，避免大面积渐变或过度拟物。贴边桌宠仍为透明背景，**绝不能显示管家界面的白色卡片底**。

**主窗口基准大小**：建议 900×630 逻辑像素，最小 760×540，支持窗口尺寸持久化与 DPI 缩放；侧栏约 176 px，顶部高度 65 px，右侧内容区可滚动。只是布局基准，不强迫改动既有大小与主题组件。

### 2.3 五个新页面

**A. 今日 / 生活状态**：左侧敲咪的展示区（现有形象和姿态），右侧四状态和三快捷按钮，底部最近一件趣事；「自动照顾自己」默认启用（已有则复用）。只展示信息，不用红色警报色渲染低数值。

**B. 玩具屋**：三种现有玩具（逗猫棒/毛线球/玩具老鼠）以及新小游戏「猜肉垫」「接小鱼」，每种卡片有“和敲咪玩”按钮；附小提示「随时可以退出，完全不用刷分」。游戏以独立轻量弹出面板或猫附近的临时对象呈现，不全屏。

**C. 秘密收藏箱**：上方纸盒插画与「敲咪今天捡到了……」，下方 3×2 收藏卡网格（图标、名字、已拥有个数/最新日期），顶部筛选“全部/最近/礼物”。收藏箱不限每日签到，不引入背包消费；重复捡到合并计数；礼物可查看故事短句。首次进入空状态展示「敲咪还没捡到宝贝，没关系呀」。

**D. 布置小窝**：左侧小房间预览（小型场景而非整屏桌宠背景），底部/右侧 8 家具图标（纸箱、猫抓板、小沙发、小地毯、小书架、小鱼缸、猫爬架、小被窝）。点击家具 → 预览 → 应用/收起；只允许一件主家具、最多两件小摆设并存，以免遮挡小猫。桌面上家具默认隐藏，用户可单独勾选「在桌面显示小道具」。房间背景只存在于小窝页面，不粘在透明桌宠窗口后。

**E. 回忆相册**：顶部“与敲咪的日子”与**可关闭回忆记录**开关；时间轴/月份筛选；每张卡片一张小插画/行为图标、一句敲咪口吻的文案、时间与事件标签；点击进入详情，可以删除单条、清空回忆、导出为 JSON（可选 CSV）；应能选择是否记录，不能擅自永久保存聊天内容。默认只存最小必要事件，不存键盘/屏幕/声音。

**F. 设置扩展（复用旧设置）**：在原设置里新增“生活趣味”折叠组：`启用鼠标观察 / 梦境气泡 / 趣味闯祸 / 自主捡拾 / 回来啦提醒 / 桌面家具显示 / 回忆记录 / 自动照顾自己`。设置实时生效、跨启动保存；声音/语音/主题/缩放旧项不改变。

### 3.1 交互与细节补充

**鼠标观察 F01 + 模仿 F06**：不要捕获/拦截所有 Windows 鼠标事件。优先复用当前猫咪小窗口的鼠标移动事件；如果需跟随窗口外附近坐标，可在普通模式下用 `QCursor.pos()` **低频采样、只记录当前必要坐标、不持久化**，仅在鼠标靠近敲咪时临时提高到约 10–15fps 进行细微动画；闲置回到极低频。鼠标指向猫头时，已有“摸头”热区判定优先。一次长按不算四次摸摸。系统级鼠标/键盘钩子禁止作为默认实现。

**收藏 F02**：使用预设物品表 `item_id / 名称 / icon / short_story`，每次掉落仅小气泡 `「敲咪捡到一颗小石头！」`；纸箱可查看、不丢失；重复物品只增加 `count`；回忆中的“礼物”通过预设事件生成，不生成需要云端请求的文本。

**做梦 F03**：只在 `RESTING / SLEEPING` 状态活动期间出现；可加极短爪爪抽动但不能制造受伤或惊吓；鼠标碰猫 / 游戏模式 / 退出 / 角色醒来必须立即清泡。与现有“梦话”效果协调，不能重复泡泡。

**家具 F04**：场景编辑采用“槽位摆放”，不是自由拖拽 3D 家具；用户可以选择一件主家具、两件装饰。不同主家具只影响自主动作选择权重，不给能力加成。所有家具都初始可用，不锁付费/每日登录。猫压在家具上时保持正确图层（猫的身体在垫子前，床毯可局部盖住下半身）。

**情绪微动作 F05**：用现有行为状态上附加 `micro_expression` 子层（闭眼/眨眼/耳朵/尾巴/轻微点头），不要再造第二套与原模型争抢调度的动画状态机。概率要低；允许用户从设置关闭。低 mood 不等于闷气状态，自动提升 mood 不可自动解闷气。

**模仿 F06**：仅对敲咪本体附近的鼠标节奏做短时、匿名的信号统计，例如 2 秒内点击 3 次触发「拍地板」；系统鼠标轨迹不入库。避免误判拖拽为抚摸、误判连续点击为四次独立安抚。人机交互优先级高于表现效果。

**闯祸 F07**：新增 4 个固定事件 `CAUGHT_SNACKING / BOX_STUCK / CHASE_TAIL / HICCUP`；外观可爱但不卡死。被发现偷吃时，猫藏鱼干并眨眼；卡纸箱点击一下即可出来，不操作也能在 10 秒内自动脱困。不能强制打断用户正常键盘鼠标输入。

**小游戏 F08**：猜肉垫用本地随机数从四只爪选一个，猫做揭晓动画；毛线球是可拖拽玩具，限定小猫附近互动区域；接小鱼由动画轨迹和随机成功/失败决定，**失败不扣任何东西**。小游戏有关闭按钮、Esc/结束可取消，取消后回原姿势，无持久高频线程。

**回来啦 F09**：与旧规则区分——旧“未直接摸猫”仍按 10/20/30 分钟；新“用户实际离开电脑”仅用 Windows 最近输入时间作**可选低频检测**。若有闷气，使用 `「妈妈回来啦……哼！」` 之类文案，但闷气与计数保持不变。若正在视频/游戏模式/全屏应用，避免突然显示，遵守隐藏与低打扰设置。游戏模式恢复只调用旧恢复事件，不叠加普通回来事件。

**回忆 F10**：仅记录对用户有意义且明确的事件，例如第一次抚摸、第一次喂食、第一次洗澡、第一次使用小游戏、第一次和好、获得特殊礼物。默认保存简短事件摘要，**不记录完整聊天内容**；提供总开关和单条删除/清空。对相同事件做去重和冷却，每天最多生成少量记录（如最多 3 条新普通回忆，首次里程碑除外）。历史记录使用本地时区显示，不从操作系统获取额外地理信息。

## 4. 事件优先级与互斥（整个项目最重要的技术设计）

建议复用现有状态机，统一管理，而不是每个功能自己 `while True` 或独立常驻线程：

```text
GAME_SLEEP  绝对最高（停止所有新增任务/计时器/模型/监听）
  > USER_TOUCH / USER_DRAG / USER_COMMAND
  > USER_FEED / USER_BATH / USER_PLAY / MINIGAME
  > EXISTING_SULK / SOOTHE (四次独立安抚)
  > AUTO_CARE（吃饭、洗澡、休息）
  > RETURN_EVENT / PRANK / DREAM / COLLECT / FURNITURE_IDLE
  > NORMAL_IDLE / MICRO_EXPRESSION
```

- 同一时间**一项主活动**；情绪微动作可以作为当前动作的一部分，但不能与洗澡、进食等互斥动作冲突。
- 一切临时事件实现 `start → cancel → finish → cooldown`，可中断且幂等。用户摸猫、切换游戏模式、关闭窗口时必须正确清理泡泡、动画、临时玩具和事件定时器。
- `return_event` 不得清除 `sulking`；猫在生闷气时可有匹配文案。原安抚计数严格按独立触摸间隔，保持现有阈值。
- 短时间多个候选事件，只挑一个，剩余候选**丢弃或重排**，不要排队堆积；游戏模式更不能补播。
- 动作/互动事件驱动可选地写回忆和收藏，但写库由统一的数据层处理，不得由动画渲染帧驱动。

## 5. 建议的软件分层（模块名仅供参考，不得假定项目已有对应文件）

```text
现有主程序 / 管家窗口 / 托盘
  ├─ 复用现有透明猫窗口、动画帧驱动、身体热区
  ├─ PetActivityCoordinator   # 唯一活动调度器；优先级/取消/冷却
  ├─ AmbientInteraction      # F01 + F06 附近鼠标观察与模仿
  ├─ PetAmbientEvents        # F03 + F05 + F07 + F09
  ├─ PetCollections          # F02 本地收藏物品
  ├─ PetFurniture            # F04 场景槽位、预设家具
  ├─ PetMinigames            # F08 低成本短游戏
  ├─ PetMemoryAlbum          # F10 事件存储、查询、删除、导出
  ├─ LocalPetPersistence     # 复用 SQLite / 现有配置迁移框架
  └─ ManagerUI               # 原有页面基础上增量增加导航与卡片
```

**数据库建议**（根据项目存储实际情况调整，不要强行套新数据库）：

- `pet_collection`: `item_id TEXT PRIMARY KEY, count INTEGER, first_found_at TEXT, last_found_at TEXT`。
- `pet_memories`: `id, event_type, occurred_at, template_id, item_id NULL, note NULL, hidden/deleted`；勿保存聊天原文。
- `pet_room`: `slot_id, furniture_id, visible_on_desktop, updated_at`。
- `pet_feature_settings`: 或现有配置对象，保存各开关、最近事件冷却时间、展示主题（不要覆盖原主题）。
- 允许在旧数据中没有这些表/键时首次初始化；对损坏记录做默认值与回滚策略；在生成新迁移前备份。

**事件数据建议**：`event_id / type / priority / allowed_states / cooldown / duration / interruptible / animation_asset / bubble_text / persistence_effect`；将玩法内容做配置驱动，避免散落在 UI 槽函数内。不要把同一事件写两次回忆或多次增加物品。

## 6. 资源清单与动画策略

**优先复用现有猫图、表情、睡姿、向尾喵睡衣、爪爪、工具图标**；新增缺失的素材用临时 SVG / 简单绘制 / 程序局部变形占位，并在报告列出真实缺失，不声称已自动产出美术。

**最小新增素材**：梦泡泡边框 1、6 个梦境图标、纸箱 1、收藏物品图标 7、8 件家具图标或轻量插画、闯祸表情/姿势 4、小游戏道具（毛线球/小鱼/四爪）3、回忆卡片插画模板 3–5。建议素材采用透明 PNG/WebP/SVG，遵守项目原资产规范；避免高频视频/GIF 解码，优先雪碧图或帧状态过渡。

**桌宠动作表现**：做不到真正骨骼动画时，可让既有 2D 猫精灵复用轻微位移、缩放、摆尾、眨眼、眼睛方向、独立泡泡层；不要用性能昂贵的全屏透明视频窗口。

## 7. 性能、兼容、隐私硬要求

1. **游戏模式**：新增的 UI、动画、观察采样、Windows 闲置检测、活动调度、DB 定时刷写全部暂停或释放；仅托盘手动唤醒保留，原有托盘可正常响应；恢复不追算历史、不自动启动队列。
2. 正常空闲时使用低频事件轮询或已有调度时钟（例如 1–3 秒一次统一调度检查，而不是每个功能单开一个定时器）；鼠标跟随仅邻近时短暂高频；动画结束回到低频。程序没有界面交互时不能持续高 CPU/GPU。
3. 不增加系统全局键盘监听、不加屏幕采集、不加云端；若使用 Windows `GetLastInputInfo` 仅判断过去多久有输入、默认设置可关闭，**不读取输入具体内容**。
4. 检查高 DPI/多显示器/贴边，100–150% 缩放；道具和弹窗不能越界。Qt 透明区域必须不吞掉其他应用操作，游戏和全屏软件优先不打扰。
5. 保存要节流：事件完结时写库、退出时同步、定期节流备份/落盘；不能在动画每帧写盘。保留原 SQLite 记忆数据库及用户手动设置。
6. 设置「减少动画」「暂时不打扰」（若原设置有同类项则直接复用）；不打扰不可替代游戏模式，但能关闭泡泡与事件；默认为温和低频，不频繁弹窗。
