# v0.6.0 P1–P3 功能候选版

本次基线为实际交付的 v0.6.0-P0-fix.1，不是从空目录重写。沿用 Python / PySide6 / SQLite / 本地语音与 Ollama。先修框架，再进入 P1、P2、P3。P4 的 Linux 与 WindowsServer2025 CI 回归、GUI EXE 构建与打包启动自检已完成；Windows11 实机验收尚未完成，不能视为最终 Windows 发布版。

## 本次审查修正

- `CompanionPolicy.can_start` 只决定入口许可。`can_continue` 校验游戏、系统休眠、任务、可见性、拖拽、保护状态和功能开关；活动用 `activate` 在发出同步 Qt phase 信号**之前**登记自己拥有的阶段。授权活动进入 `companion/minigame/daily` 后不再因入口仅许 idle 而被立即取消；摸猫、拖拽、照顾、隐藏、关闭仍能取消。
- 短事件仍最多 10 秒；F08 租约上限 300 秒，实际小游戏 120 秒。独立结束定时器 + 统一策略刷新均可收回租约。关闭、Esc、超时、禁用、触摸、系统休眠、游戏深眠都清理游戏及局部动画定时器。
- 原 `dream_enabled` / `bubbles_enabled` 与新 F03 **共同生效**；不会强制改写旧用户开关。关闭任意一项即停止梦泡，重新开启可重新调度；减少动画和不打扰也会禁止梦泡。只有原梦话计时器负责睡眠调度，不再双重生产。
- 升级继续保留旧 P0 快照的兼容处理；新增一次 `0.6.0` 快照，记录代码基线 `0.6.0-p0-fix.1 -> 0.6.0`，同时使用 SQLite online backup 备份现存 `*.db`，包括 WAL 已提交内容。原记忆库 Schema 未变。

## 数据与隐私

- 原 `qiaomi.db`、语音配置、个人偏好不做新 Schema 迁移。`companion.json` 保存新开关；`companion.db` 保存物品、房间、事件摘要及防重复收据。
- 收藏与相册写入在同一事务内；失败回滚。动画取消不会撤销已入箱物品。关闭 F10 不再记录新相册，但 F02 可以继续捡物品。
- 删除/清空相册保留最小事件 ID 收据，防止“首次”卡片重启后重新出现；收据不含事件正文。导出只含小世界数据，不包含私人聊天与长期记忆。
- 不新增后台音频、模型调用、全局键盘钩子、屏幕捕获。短时鼠标统计仅内存，拖拽/深眠即清除。
- 原 264 个运行资源保持逐文件 SHA256 一致，角色、睡衣、图标均未重绘。此前素材已有候选美术限制不因此被宣称通过。

## 游戏模式

仍只允许托盘明确唤醒；新页面入口/小游戏/趣味设置不能唤醒。进入深眠会取消活动、清除邻近鼠标统计、停止陪伴/小游戏/语音/旧生活动画计时器，不补播积压事件、不补扣数值；只保留原托盘保活检查。普通回来不叠加到游戏唤醒重逢。四次独立摸摸仍由原 Life/Personality 状态机计算，未以连续点击代替。
